# 收尾汇报

只有负责人使用。中途不发，只在这两种时候发：

- 一批任务全部合并后：发一条汇总。
- 有任务挂起，或上线检查不通过、已回滚：立刻单独发一条。

向用户提问一律用提问器（AskUserQuestion 工具），不在正文里问。

## 步骤

1. 先更新 Notion「📁 项目」下这个项目自己的「<项目名> 任务」库里相关的任务卡：状态写在「状态」列；模型和档位、失败次数、分支写进「备注」，token 用量写进「备注」的「token 用量」。挂起的标「卡住」，原因写进「卡在哪」。
2. 再发 Slack：按用户全局 CLAUDE.md 里的 Slack 汇报规则发，频道、@谁、写什么都以那里为准。
3. 同一件事只发一条。全局规则已经要求收尾发汇报的，这一条就是它，不要再发第二条。
4. 全局规则里没有 Slack 汇报规则时，用提问器问用户发到哪。
5. 挂起或回滚的汇报要写清：卡在哪、试过什么（模型和档位）、需要谁做什么。上线检查「无法判断」时，写明没法确认线上情况。
6. 汇报里带任务卡链接。
7. 一批任务的汇总，先有任务说明页：负责人派 dev-haiku（档位低）用现成材料（派活单、交回摘要、验收和审核结论、改动文件清单）写短 Markdown，并自己用 answer-me-with-html 技能跑 `am render` 排成一页 HTML，交回文件路径（默认在 `~/.answer-me-with-html/pages/`）。负责人用 Artifact 工具把它发布成私有页面，汇总和任务卡里贴拿到的 claude.ai 链接（本机路径在手机上打不开）；没有 Artifact 工具才退回贴本机路径。小改动和快修不单独写；PPT 只在用户点名时做；没装这个技能就跳过，在汇报里写一句「没装 answer-me-with-html，未生成说明页」。
