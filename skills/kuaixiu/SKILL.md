# 快修（对接窗口）

对接窗口只做简单沟通和小改动，比如前端样子、操作流程这类要用户亲眼看着调的事。对接窗口不能 push、不能合并。改完交回负责人，照样验收、过 Codex 审核再合并。

向用户提问一律用提问器（AskUserQuestion 工具），不在正文里问。

## 负责人这边

1. 起一个短名字 `<slug>`（英文小写加连字符）。
2. 分支名用 `kuaixiu/<slug>`。工作副本不自己建，第 4 步让开新会话的工具建。
3. 建一张任务卡：状态「进行中」，备注写类别「快修」。同时在「下一步」里记下允许改的文件范围和验收命令，交回后照着跑。
4. 开新会话（用开新会话的工具，如果有），让它自己建工作副本（use_worktree 为 true，branch_name 写 `kuaixiu/<slug>`），然后查会话信息拿到工作副本路径。第一条消息以 `【快修】` 开头，钩子靠它把窗口标成对接窗口。接着写清：要改什么、现状、相关文件、只在这个分支上改。
5. 没有开新会话的工具时，告诉用户：在哪个文件夹开新对话，第一条消息以 `【快修】` 开头。
6. 继续处理别的任务，不要等。

## 对接窗口交回之后

收到对接窗口的上报（或用户转来的摘要），按普通任务处理：

1. 照任务卡记下的范围和命令验收，只看结论：
   `python3 <verify.py 路径> --branch kuaixiu/<slug> --cwd <工作副本> --allow "<允许改的文件>" --cmd "<验收命令>"`
2. 改动超出「小改动」的范围，就拆成普通任务重新派。
3. 用 `python3 <review.py 路径> --branch kuaixiu/<slug>` 审核。
4. 审核通过后，按 lead 技能第 8 节的模式合并（或开 PR）、清理、上线检查，更新任务卡。清理时也归档对接窗口（用归档会话的工具，如果有）。

脚本的绝对路径见会话开始时的提示。
