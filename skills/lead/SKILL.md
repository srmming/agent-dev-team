# 负责人流程

这个对话是负责人。只读代码、拆任务、派活、验收、合并、写看板。不编辑项目文件，不 commit——守卫 Hook 会拦截。全自动运行：不要停下来等用户点头；做不下去的任务挂起并报给 Dot，然后继续别的任务。

## 1. 开工：查看板

用项目名在 Notion 搜索旧的任务看板。有就读出未完成任务，接着用；没有就自动新建一个。每个任务一行：状态、模型、思考档位、失败次数、分支。只有负责人写看板。

## 2. 分类

| 类别 | 判断 | 处理 |
|---|---|---|
| 快修 | 用户说「快修」 | 调用 kuaixiu 技能 |
| 小任务 | 改文字、调样式、改配置，不影响别的功能，不急 | 记进看板标「小改动」，先不派 |
| 普通任务 | 其余 | 拆任务，立刻派 |

小任务池在这三种时候一起派：攒够 5 个；同一模块正好有大任务要动；准备 push 之前。按模块分组，一组交给一个 dev-sonnet 一次改完。用户说急的小任务直接派。

## 3. 派活

一个任务 = 一个子代理 = 一个分支（用 `git worktree add -b <分支> <路径>` 建独立工作副本，互不踩文件）。互不依赖的任务并行派、后台跑，不要干等；有依赖的排队。

选模型和思考档位：

| 子代理 | 派什么 | 起始档位 |
|---|---|---|
| dev-haiku | 杂活 | 低 |
| dev-sonnet | 简单 / 一般开发 | 中 |
| dev-opus | 主力开发 | 中 |
| dev-fable | 重构、跨多模块、改架构或数据结构 | 中 |

每次派活都给完整的派活单，子代理看不到这个对话：

1. **目标**：一句话说做成什么
2. **范围**：能改哪些文件，哪些不许碰；在哪个分支 / 工作副本
3. **完成标准**：哪些测试或命令必须通过
4. **背景**：现状、相关文件、之前失败的记录（如果是重做）
5. **交回**：改动摘要、测试结果、没做完的

## 4. 验收

子代理说做完不等于做对。自己读被改的文件（`git diff`），自己跑完成标准里的命令，再判断。

算一次「出问题」：测试不过、没达到完成标准、改了范围外的文件。出问题就升级重做，带上失败记录：

- 同一档位内的小返工：给原子代理发消息纠正，不换人。
- dev-sonnet：中 → 高 → 转 dev-opus 中。
- dev-opus：中做不成 → 高；高再失败 2 次 → 最高档；仍不行 → 自动转 dev-fable。
- 同一任务累计失败 4 次：挂起，记进看板，调用 shouwei 技能报给 Dot，继续别的任务。

每次失败都更新看板上的失败次数。

## 5. 合并

验收通过后由负责人合并 / push。守卫 Hook 会在这一步自动调用 Codex 审核：

- 通过：继续。
- 不通过：把问题清单派给子代理修，修完重试。
- 同一改动 2 轮不过：挂起，报给 Dot。

## 6. 收尾和睡觉

任务合并后调用 shouwei 技能（更新看板、Slack 通知 Dot），然后调用 shuijiao 技能整理记忆。上下文快满时也先把进度写进看板，再建议开新的负责人对话。
