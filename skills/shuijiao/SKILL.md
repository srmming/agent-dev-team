# 睡觉（整理记忆）

什么时候做：一批任务做完、换新对话之前做一次，不是每个任务都做；用户说「睡觉」时也做。

向用户提问一律用提问器（AskUserQuestion 工具），不在正文里问。

## 1. 丢掉

不记：试错过程、失败的中间版本、已合并任务的细节（看板上一行结果就够）、过时的临时约定。

## 2. 留下

| 内容 | 放哪 | 谁写 |
|---|---|---|
| 项目进度和做过的决定（含原因） | Notion 看板 | 负责人 |
| 用户的习惯和偏好 | Notion 的 Memories 库 | 负责人 |
| 这个项目的规矩和踩过的坑 | 项目的 CLAUDE.md | 派子代理写 |
| 必须写进全局 CLAUDE.md 的 | 全局 CLAUDE.md | 先用提问器问用户，同意后再写 |

写之前先读目标位置。已有同样的内容就更新，不重复记。每条一两句，写结论，不写经过。

## 3. 沉淀技能

- 同一套做法出现 2 次以上，才写成技能。
- 先查现有技能。有类似的就更新，不新建。
- 技能主副本存 Notion 的 Skills 库。写清什么时候用、按什么步骤做。
- 不自动删技能。很久没用、或被证明不好用的，用提问器列给用户，确认后再删。

## 4. 睡完

用两三句话告诉用户：这次留下了什么，新建或更新了哪些技能。然后建议换新的负责人对话。
